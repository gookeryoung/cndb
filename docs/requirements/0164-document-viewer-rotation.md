# 0164 文档阅读器旋转与镜像（S2）

Status: 已确认并落地（2026-11-26 评审通过；P0-P2 已完成）
Related: `frontend/src/pages/documents/DocumentAssetView.tsx`、`frontend/src/api/documents.ts`、`src/cndb/plugins/documents/routers/documents.py`、ADR 0025、ADR 0129

## 需求原句

> 文档，PDF类文档的查看，提供自动旋转功能按钮，对于需要旋转的判断正确的方向后默认自动旋转，右侧提供并列的手动旋转90°和反转的操作按钮。

## 已确认选型（2026-11-26 人工回答）

| 议题 | 结论 |
|---|---|
| 覆盖范围 | PDF + 图片原件（PPTX 衍生 PDF 沿用同一 PDF 路径，不单独做） |
| 「反转」语义 | **水平镜像翻转**（不是逆时针 90°，也不是 180°） |
| 自动旋转判定 | 元数据优先（图片 EXIF / PDF 页面 `/Rotate`）+ 长宽比兜底，仅高置信度才自动应用 |
| PDF 手动旋转实现 | 后端用 pypdf 生成旋转 / 镜像副本，前端 iframe 重载；不引入前端 pdf.js |

## 约束（C1..C7）

| # | 约束 | 验收 |
|---|---|---|
| C1 | 旋转 / 镜像控件只对 PDF 与图片原件出现；其它格式（Office / MHTML / PPTX 客户端预览 / 下载卡）不出现 | 非 PDF / 图片文档不渲染控件条 |
| C2 | 控件条位于阅读区右侧，手动「旋转 90°」与「水平镜像」两个按钮**并列**；另有独立的「自动旋转」开关按钮 | 三个控件同一条，两个手动按钮横向相邻；有 tooltip 与 aria-label |
| C3 | 自动旋转默认开启；判定到高置信度方向时默认自动应用；判定不确定时不自动旋转 | 有 EXIF 的图片按 EXIF 呈现；PDF 按页面 `/Rotate` 呈现；无依据时不改动方向 |
| C4 | 手动操作可叠加、可回环：旋转每次 +90°（0/90/180/270 循环），镜像可开可关；关闭自动旋转回到原始方向 | 连续点击 4 次回到原方向；重新打开自动旋转重新套用判定结果 |
| C5 | PDF 旋转 / 镜像不改原件，只生成派生副本；仍使用浏览器原生 PDF 阅读器 | 旋转后原件接口字节不变；阅读器 iframe 内仍是原生 PDF UI |
| C6 | 权限、只读、下载、可见性口径不回归；图片旋转是纯前端显示变换 | 越权仍 403/404；下载仍拿到原件；图片下载不受显示方向影响 |
| C7 | 切换文档时方向状态重置；Chrome 81 可用；不新增首屏重依赖 | 切换文档后控件归位；旧内核冒烟通过；pypdf 只在后端 |

## 不做

- 不做基于 OCR / 图像内容识别的方向判定（需要重型模型或渲染链路，本需求范围外）。
- 不引入前端 pdf.js，不改 ADR 0025 D8 的「浏览器原生 PDF 渲染」主路径（仅派生副本走服务端）。
- 不改原件字节、不新增「保存旋转」到文档模型。
- 不做旋转状态跨会话持久化。

## 立项说明

现有阅读器（ADR 0025）PDF 走 `<iframe>` 原生渲染、图片走 `<img>`，都没有任何方向控制；
扫描件横置时用户无法在应用内摆正。本需求补「自动判定 + 手动纠偏」的最小闭环，
且必须在不破坏只读原件、权限与 Chrome 81 兼容的前提下落地。
