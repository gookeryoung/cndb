## 可实施约束（C1..C6）

| # | 需求句（原文片段） | 可实施约束 | 涉及模块 | 验收方式 |
|---|---|---|---|---|
| C1 | 「健壮性」 | **保留期可配**：`AUDIT_RETENTION_DAYS` 默认 180，`0` = 关闭（永不自动清理），负值同 0 | `core/config.py` | 单测：默认值 / 0 关闭 / 负数按 0 |
| C2 | 「审计」 | **按保留期清理** `tables_auditlog`：只删 `created_at < now - days` 的行，分批（默认 1000 行/批），返回逐表与总计数 | `services/core/audit_retention.py` | 单测：过期删 / 未过期留 / 分批 / 幂等 |
| C3 | 「事件流」 | 同一入口清理统一事件流 `core_event`（同阈值、同分批）；两张表任一为空也不报错 | 同上 | 单测：两表各自过期行被清理 |
| C4 | （可恢复性） | **`dry_run` 只报告不删除**（默认），`--apply` 才删；CLI 为 `cndb tables purge-audit [--days N] [--apply] [--json]` | `cli/tables.py` | 单测：dry-run 不改库 / apply 真删 |
| C5 | （不做的影响） | 流水不参与工作区备份（既有 ADR 0075 口径），因此清理**不影响备份往返**；`tables_auditlog` 仍是行历史的唯一来源，清理后旧记录不可恢复——因此默认 180 天、只按时间不按条数 | 全仓 | 备份测试不受影响（既有用例全绿） |
| C6 | （可观测） | 返回报告含 `cutoff` / `days` / `audit_deleted` / `events_deleted` / `tables`，CLI 人读输出给出一眼可读摘要 | 同上 | 单测：报告字段 + 人读包含关键数字 |

约束编号在实现中原样引用；不重编号、不合并。

## 现状影响面

| # | 疑似受影响能力 | 候选位置 | 备注 |
|---|---|---|---|
| 1 | 行审计写入 | `services/core/audit.py::log_action` | 每次行写都插一条，含 `detail` 行快照（大字段），长期无上限 |
| 2 | 统一事件流 | `core/events.py::record_event` | 各域都在写，同样无上限 |
| 3 | 审计读接口 | `routers/audit.py` | 已有按 action / row_id 过滤 + 行级过滤，本期不改 |
| 4 | 备份 | `workspaces/services/workspace_backup.py` | 流水不进备份（ADR 0075），清理与备份互不影响 |
