# 需求卡片：用户自助修改密码与管理员重置他人密码

- 编号：0050（与 ADR `docs/adr/0050-*.md` 同号）
- 来源 / 提出人：用户（2026-10-27 会话）
- 日期：2026-10-27
- 关联 ADR：`docs/adr/0050-user-password-management.md`（Proposed，待评审）

> 本卡片是**需求原文与约束编号的唯一副本**：ADR 只引用 C1..Cn，不复制原文；需求澄清后先改这里，再同步 ADR「口径」表。

## 需求原句（逐字）

> 增加用户修改密码，以及管理员修改其他用户密码的功能。

## 可实施约束（C1..Cn）

| # | 需求句（原文片段） | 可实施约束 | 涉及模块 | 验收方式 |
|---|---|---|---|---|
| C1 | 用户修改密码 | 已登录用户可在「个人设置」中修改**自己的**密码：必须同时提供当前密码与新密码（新密码 6–128 位，且不得与当前密码相同）；当前密码错误或新旧相同返回 400 中文明细 | 后端 `accounts/routers/auth.py` 既有 `POST /api/v1/accounts/auth/password`；前端新增个人设置页签 / 面板 | 接口层：正确旧密码改密成功、错误旧密码 400、新旧相同 400、未登录 401；前端单测：表单校验与提交 |
| C2 | 用户修改密码 | 改密成功后立即使该用户**全部会话失效**：`token_version` +1（既有 access token 立即失效）并吊销全部刷新令牌；前端清空本地登录态并跳转登录页，提示重新登录 | 后端既有改密逻辑；前端 `store/auth.ts`、`SettingsModal` | 接口层：改密后旧 access token 401、旧 refresh token 不可用、旧密码无法登录；前端单测：成功后退出登录 |
| C3 | 管理员修改其他用户密码 | 超级管理员可在「管理台 → 用户管理」对**其他用户**重置密码：无需输入目标用户当前密码；新密码来源二选一——默认由服务端生成 12 位随机密码并仅在本次响应中展示一次，也可由管理员手工输入（6–128 位）；成功后目标用户全部会话失效（`token_version` +1 + 吊销全部刷新令牌），目标用户需用新密码重新登录 | 新增 `accounts` 用户管理端点（候选 `POST /api/v1/accounts/users/{user_id}/password`）与服务层；前端 `UsersPage` 操作列 | 接口层：非超管 403、目标不存在 404、超管重置成功且目标旧会话失效、目标可用新密码登录、自动生成与手工输入两条路径；前端单测：入口 / 表单 / 二次确认 / 生成密码展示 |
| C4 | 管理员修改其他用户密码 | 管理员重置端点**拒绝作用于管理员自己**（返回 400，提示改用个人设置并校验当前密码），避免管理员绕过旧密码核身 | 后端用户管理服务层 | 接口层：超管重置自己 400 且密码不变 |
| C5 | 隐含（审计与事件） | 管理员重置写入用户管理操作日志（动作 `password_reset`，仅记录操作人 / 目标 / 是否自动生成等元信息，**不记录重置原因**），并进入统一事件流；**不得记录明文密码或哈希**；前端操作日志动作标签可读 | 后端 `services/users.py`、`core/events.py`；前端 `UsersPage` 动作标签与日志抽屉 | 接口层：重置后审计记录存在且 detail 不含密码；前端单测：动作标签渲染 |
| C6 | 隐含（权限边界与零回归） | 普通用户只能改自己的密码；管理员重置仅超级管理员可用（安全管理员 / 审计管理员均 403）；既有注册、登录、导入导出、编辑用户等接口契约不变 | `accounts` 插件、现有前端页面 | 接口层权限矩阵；既有 `tests/test_auth_*`、`tests/test_users_*` 全绿 |
| C7 | 隐含（密码不落明文） | 新密码只以 bcrypt 哈希落库；手工输入的新密码永不回显，自动生成的密码**仅在该次重置响应中返回一次**；操作日志、事件、列表 / 导出接口均不含密码 | 后端 `User.set_password` / `hash_password`；前端表单 | 接口层断言响应与审计无密码（自动生成场景仅校验一次性字段）；代码评审 |

约束编号在 ADR 中原样引用；不重编号、不合并。

## 未决问题

- [x] **Q1 管理员重置是否需要目标用户当前密码**——结论（需求方 2026-10-27 确认）：不需要，核身由超级管理员角色保证。
- [x] **Q2 管理员能否通过用户管理重置自己的密码**——结论（需求方 2026-10-27 确认）：不能，返回 400 引导走个人设置。
- [x] **Q3 自助改密成功后前端是否强制退出并跳登录页**——结论（需求方 2026-10-27 确认）：是，强制退出并重新登录。
- [x] **Q4 密码规则**——结论（需求方 2026-10-27 确认）：沿用现有 6–128 位，不新增复杂度强制。
- [x] **Q5 管理员重置的新密码由谁提供**——结论（需求方 2026-10-27 确认）：默认服务端生成 12 位随机密码并展示一次，同时允许管理员手工输入。
- [x] **Q6 是否要求目标用户下次登录强制改密**——结论（需求方 2026-10-27 确认）：本期不做。
- [x] **Q7 审计粒度**——结论（需求方 2026-10-27 确认）：只记录动作与操作人 / 目标 / 是否自动生成，不记录重置原因。
