# 需求卡片：顶部导航三区划分与主页跨工作区搜索

- 编号：0081
- 来源 / 提出人：用户（2026-11-01 会话）
- 日期：2026-11-01
- 关联 ADR：无（S1 常规功能：前端导航重构 + 一个只读检索端点，无数据模型 / 权限 / 架构分叉）

> 本卡片是**需求原文与约束编号的唯一副本**：ADR 只引用 C1..Cn，不复制原文；需求澄清后先改这里，再同步 ADR「口径」表。

## 需求原句（逐字）

> 请针对导航设计进行优化重构：1.顶部导航按照左、中、右区域划分。右侧区域内容维持当前现状。将工作区内的搜索功能复制到主页显示，即进入工作区前也可搜索。2.将数据表、文档、设计和工作区设置这四个工作区一级功能模块挪到顶部显示，数据分析、质量检查等二级功能模块维持当前位置。

## 方案口径（关键决策）

| 决策 | 结论 | 理由 |
|---|---|---|
| 主页搜索的实现载体 | **后端聚合端点** `GET /api/v1/search`，逐工作区复用既有 `search_workspace`（scope=all），单请求返回 | 前端扇出 = 每次按键 N 个请求且无法统一全局上限；服务端聚合单请求、可收敛配额，且与既有「检索是服务端能力」的口径一致（ADR 0015） |
| 全局结果配额 | 每工作区文档 / 表名各 ≤3、行 ≤3；全局文档 / 表名 / 行各 ≤10 | 主页搜索的定位是「找到在哪个工作区」，不是穷举；面板展示预算与既有 MAX_ITEMS=20 对齐 |
| 主页模式的范围选择器 | 隐藏（恒为全部：文档 + 数据表） | 「数据表 / 文档」范围收敛依赖表上下文（table_id/view_id），主页无上下文 |
| 排序 | 工作区按 pinned → id（与工作区列表一致），组内保持既有顺序 | 与主页列表视觉顺序一致，可预期 |
| 移动端 | 顶栏三区划分照常适用（左区不放一级模块导航），一级模块维持页签行现状 | 375px 顶栏放不下四个导航项；移动端交互零回归 |
| 分级 | S1，不立 ADR | 无数据模型 / 迁移 / 权限口径变化；新增端点为只读聚合，复用既有成员权限判定 |
