## 二、批次计划

### 批次 0：收尾（先做，0.5 天）

1. 提交 0168–0171 + 自查修复（当前 40+ 文件未提交，风险随改动累积）。
2. 版本 bump / tag（沿用 `make bump` / `make push`）。
3. 回填 0168–0171 卡片的提交 sha（当前为「待提交」）。
4. 遗留小项作为同一版本的维护提交，避免单独占一个版本号。

验收：`make flow`、`make check-frontend` 全绿；`git status` 干净；卡片 sha 回填。

### 批次 1：低风险 S1（3–4 天）

0172 文档副本 → 0173 事件审计 → 0174 附件面板。顺序理由：三项都不动权限面与正文模型，
且都能复用现有能力（`move.py` 的文件复制、`core/events.py`、`docs gc`），可并行评审。

验收要点：
- 0172：复制文件夹含子树；标题重名递增；附件按键复制；配额预判；跨工作区不复制。
- 0173：写路径事件只记定位信息（不落正文）；管理台按 action / 时间 / 操作者过滤。
- 0174：列表分页 + 引用文档跳转；孤儿体检 dry-run 与回收分离；回收需二次确认。

### 批次 2：需 ADR 的 S1（1–1.5 周）

0175 正文批注、0176 文档级 ACL。两项都要先出 ADR 再开卡：

- 批注的锚点稳定性（编辑后偏移、块模型迁移后的重锚）是主要风险，ADR 需定锚点格式与降级策略。
- ACL 与 H33（草稿可见性）、H64（`resolve_capabilities`）的边界必须先定，禁止出现「管理面产数据面」的旁路
  （ADR 0161 的教训）。

### 批次 3：S2（先 ADR，后实施）

0177 块级模型优先，0178 反链索引紧随其后。理由：反链索引的行级定位依赖块 id，块模型未定稿就做索引会返工；
图谱（0168）基于标题双链，块模型落地后需同步评估链接解析口径。

块模型 ADR 必须先回答：块 id 生成与稳定策略、与现有 Markdown 全文的双向兼容、版本 diff 粒度、
导入导出（Obsidian / docx / pdf）、协作（未来 OT/CRDT）的预留。

### 批次 4：技术债（按需）

对象存储（附件与大文件）、增量版本（当前每版全量快照）、`content.py` 拆分（已超 1200 行，
本轮又新增图谱聚合）、帮助教程补齐。均不进关键路径。
