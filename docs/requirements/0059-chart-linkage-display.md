# 需求卡片：图表设计器联动单元格「(计算)」显示与默认联动态

- 编号：0059（与 ADR `docs/adr/0059-chart-linkage-display.md` 同号）
- 来源 / 提出人：用户
- 日期：2026-10-28
- 关联 ADR：`docs/adr/0059-chart-linkage-display.md`

> 本卡片是**需求原文与约束编号的唯一副本**：ADR 只引用 C1..Cn，不复制原文；需求澄清后先改这里，再同步 ADR「口径」表。

## 需求原句（逐字）

> 双轴柱线组合图，主值和次值联动机制完善，联动项风格按当前形式，数值后增加(计算)表示联动值；默认次值直接显示为联动状态；点击联动项单元格后，进入编辑状态，仅显示数值不显示(计算)，对应主/次值单元格变为联动状态。请完善该设计，并一并完善其他类图表。

## 可实施约束（C1..Cn）

| # | 需求句（原文片段） | 可实施约束 | 涉及模块 | 验收方式 |
|---|---|---|---|---|
| C1 | 「联动项风格按当前形式，数值后增加(计算)表示联动值」 | 处于联动状态（显示值由配对单元格推算得出）的单元格，沿用现有底色高亮风格，非编辑态在数值后追加「(计算)」后缀（如 `12.3(计算)`） | frontend `ChartDesignerModal.tsx` | 前端单测（联动单元格显示含「(计算)」） |
| C2 | 「默认次值直接显示为联动状态」 | 新建/打开双轴图表设计器时，次值留空且可推算的行（i≥2）直接按主值推算显示增速值并处于联动状态（带高亮 +「(计算)」）；第 1 行仍禁填；实际存储仍为 `null` | frontend `ChartDesignerModal.tsx` / `chartLinkage.ts` | 前端单测（默认打开次值列显示推算值 +「(计算)」，payload 中 growth 仍为 null） |
| C3 | 「点击联动项单元格后，进入编辑状态，仅显示数值不显示(计算)」 | 点击/聚焦联动单元格进入编辑时，输入框仅显示纯数值（推算值作为编辑起点，不带「(计算)」后缀），可直接修改 | frontend `ChartDesignerModal.tsx` | 前端单测（聚焦后输入框值为纯数字） |
| C4 | 「对应主/次值单元格变为联动状态」 | 编辑联动单元格并提交（失焦/回车）后：该单元格转为显式值（去掉「(计算)」）；对应配对单元格被重算并进入联动状态（显示推算值 +「(计算)」+ 高亮）；联动公式与舍入口径沿用 ADR 0056 D2/D3（互逆、不跨行级联、基数缺失不联动） | frontend `chartLinkage.ts` / `ChartDesignerModal.tsx` | 前端单测（编辑次值 → 主值联动显示「(计算)」；清空次值 → 恢复按主值推算的联动显示） |
| C5 | 「完善该设计」 | 提交的 config 结构不变（`label`/`value`/`growth`），不含任何联动标记；次值未被显式编辑时保存值仍为 `null`，渲染端留空推算行为不变 | backend `registry.py` / frontend | 单测 + 前端单测（payload 无标记字段、growth 为 null） |
| C6 | 「一并完善其他类图表」 | 联动显示机制沉淀为通用「派生单元格模式」；当前其余模板（水平堆叠条形图、水平分组条形图）无数值派生关系，行为不变（范围口径见未决问题 Q2） | frontend / backend | 既有堆叠/分组测试回归通过 |

## 未决问题

- [x] Q1：联动单元格「确认采纳」语义 —— 编辑联动单元格但数值未改动时，失焦后**保持联动态**（仍显示「(计算)」，存储仍为 null）；只有实际改动数值才转为显式值（需求方确认，2026-10-28）。
- [x] Q2：其他图表范围 —— **仅将联动显示机制泛化为通用「派生单元格模式」，堆叠 / 分组模板行为不变**，不新增派生能力（沿用 ADR 0056 D5 否决结论；需求方确认，2026-10-28）。
- [x] Q3：联动显示值舍入口径 —— **沿用一位小数**（与 `render.py` `growth_at` 同一舍入口径，设计器显示与渲染一致）（需求方确认，2026-10-28）。
