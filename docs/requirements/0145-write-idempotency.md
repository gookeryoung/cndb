## 可实施约束（C1..C6）

| # | 需求句（原文片段） | 可实施约束 | 涉及模块 | 验收方式 |
|---|---|---|---|---|
| C1 | 「幂等」 | 同一 `(user, key, route)` 的写请求只执行一次；重复请求**回放首个响应**（状态码 + body），不重复落库 | `services/core/idempotency.py`、`routers/records.py` | 接口测试：同 key 两次建行只落 1 行、返回同一 id |
| C2 | 「键的作用域」 | 键按用户 + 路由隔离；不同用户 / 不同路由的同名 key 互不影响 | 同上 | 单测：不同 user / route 不复用 |
| C3 | 「冲突」 | 同一 key 复用到**不同请求体** → 409（不把 A 的响应回放给 B） | 同上 | 接口测试：同 key 不同 body 409 |
| C4 | 「兼容」 | 未提供 `Idempotency-Key` 时整条链路 no-op，行为与改造前逐条一致 | 同上 | 存量测试全绿 + 单测（无 key 两次都落库） |
| C5 | 「失败可重试」 | 只登记 2xx 结果；失败不写登记，客户端重试会重新执行 | 同上 | 单测：失败后同 key 可重试成功 |
| C6 | 「保留期」 | 键默认保留 24 小时（超期视同未命中并清理），提供 `purge_expired_keys()` 供运维调用 | 同上 | 单测：超期键被清理 + 视同未命中 |

约束编号在实现中原样引用；不重编号、不合并。
