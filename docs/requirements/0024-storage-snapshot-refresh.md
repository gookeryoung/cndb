# 需求卡片：管理台「空间分配」秒开 + 后台定期同步用量

- 编号：0024（与 ADR `docs/adr/0024-storage-snapshot-refresh.md` 同号）
- 来源 / 提出人：项目所有者（管理者使用反馈）
- 日期：2026-10-24
- 关联 ADR：`docs/adr/0024-storage-snapshot-refresh.md`

## 需求原句（逐字）

> 进入空间分配页面显示刷新明显卡顿，请给出更人性化的设计，如后台定期同步更新数据，显示时立即出结果。

## 可实施约束（C1..Cn）

| # | 需求句（原文片段） | 可实施约束 | 涉及模块 | 验收方式 |
|---|---|---|---|---|
| C1 | 「显示时立即出结果」 | 管理台「空间分配」GET 只读已落库的用量快照，请求内不得执行全量统计（附件目录遍历 / 文档正文汇总 / 数据表逐行字节累加） | `core/system_api.py`、`workspaces/services/` | 接口用例断言统计函数未被调用；快照就绪时响应时不随工作区数据量增长 |
| C2 | 「后台定期同步更新数据」 | 进程内后台刷新器按固定周期（默认 300s，可配）重算全部工作区用量并落库；应用启动后自动开启、关闭时干净退出 | `app.py`（lifespan）、新刷新器模块 | 后台线程启停用例 + 线程/事件日志 |
| C3 | 更人性化（数据新鲜度） | 页面明确展示「数据更新于 X 前」与自动同步周期；用量缺失（尚未统计）时显示「统计中」占位而非 0 | `StoragePage.tsx`、`api/admin.ts` | 组件用例：新鲜度文案、占位态 |
| C4 | 更人性化（可控） | 提供「立即刷新」入口：异步触发后台重算，界面显示统计中并自动回填结果，不阻塞交互 | 同上 + `POST /admin/workspaces/storage/refresh` | 组件用例：点击后轮询到新 `computed_at`；接口用例：立即返回 202 |
| C5 | 既有口径不变 | 用量口径与现状完全一致（附件 + 文档外存 + 内联正文/草稿 + 数据表记录与回收站影子表），仍按工作区归属 | `workspaces/services/storage.py` | 复用既有口径单测；快照值与同步计算值一致 |
| C6 | 其他入口同样受影响 | 工作区详情 `storage_bytes`、上传前配额校验、配额调整返回值一并改读快照，避免其他路径重复全量统计 | `workspaces/routers/workspaces.py`、`tables/routers/files.py`、`core/system_api.py` | 接口用例：三个入口均不触发统计 |
| C7 | 变更后用量应及时反映 | 配额调整 / 附件上传后立即标记该工作区待刷新（上传按增量乐观累加），下一轮或即时刷新校正 | 同上 + 刷新器 | 接口用例：上传后快照值增加、脏标记生效 |

## 未决问题

- [x] 快照周期取值：默认 300s（管理台数据，5 分钟粒度足够；可配 `0` 关闭定时刷新）
- [x] 多进程部署：单机 SQLite 场景每进程各跑一份；刷新写入幂等（upsert），无交叉写错风险
- [x] 统计口径是否顺带 SQL 化：本期不改口径，仅把计算搬到后台；SQL 化留作后续优化
