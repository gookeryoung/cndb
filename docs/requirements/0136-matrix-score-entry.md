# 需求卡片：评分矩阵（网页内按对象 × 月份直接录入）

- 编号：0136
- 来源 / 提出人：用户（会话 2026-11-15）
- 日期：2026-11-15
- 关联 ADR：`docs/adr/0136-matrix-score-entry.md`（S2，方案评审通过后进入实现）

> 本卡片是**需求原文与约束编号的唯一副本**：需求澄清后先改这里，再同步 ADR「口径」表。

## 需求原句（逐字）

> 数据表，对于部门绩效评分这种情况，评分对象都是固定的，评分和月份需要变化，每次新增单个很慢，有无可行的机制

> 如果在网页操作有无更好的办法实现

澄清答复（2026-11-15）：

1. 每月评分对象：**20 个**
2. 新月份行分数：**留空**
3. 部门清单：**固定下拉**
4. 权限：**按通用逻辑**
5. 方案：**直接上 P2（矩阵录入）**

## 可实施约束（C1..Cn）

| # | 需求句（原文片段） | 可实施约束 | 涉及模块 | 验收方式 |
|---|---|---|---|---|
| C1 | 「评分对象都是固定的」「固定下拉」 | 行轴对象来自**单选字段的完整 options**，不依赖表内已有行。即使是本月还没有任何评分行，20 个部门也必须全部出现在矩阵中 | `frontend/src/pages/grid/views/MatrixView.tsx`、`matrixBoard.ts`、`viewOptionSchema.ts` | 前端单测：零数据时仍渲染 20 行 × N 列 |
| C2 | 「评分和月份需要变化」 | 列轴为**月份范围**（`YYYY-MM`），由视图配置起止月份生成，不依赖表内已有行。列范围上限 24 个月；范围外月份不显示 | 同上 + 后端视图配置校验 | 单测：起止月份、空月份列、跨年、超 24 个月拒绝 |
| C3 | 「每次新增单个很慢」 | 矩阵单元格直接录入得分，**按单元格保存**（失焦 / 回车提交），不要求先新增行、再逐行打开编辑。新单元格保存时自动创建对应行；已有行只更新得分 | `MatrixView.tsx`、`GridPage.tsx`、`records` 写路径 | 前端单测 + e2e：20×12 场景录入 2 格并刷新后值仍在 |
| C4 | 「评分对象固定、月份变化」 | 表结构保持**长表**：一行 = 一个对象 × 一个月份。唯一业务键 =（对象字段, 月份字段）。不得改成「一月一列」的宽表 | 数据表字段约定，无模型变更 | 接口测试：新建 / 更新 / 重复行判定 |
| C5 | （写入语义） | 按业务键 upsert：已有行 → 只更新评分；无行 → 新建（月份统一存当月 1 日）；评分为空 → 不新建空行，已有行置空。同一业务键存在多行 → **409 拒绝写入**并给出重复行 id，不静默挑一行改 | `tables/routers/records.py`、`tables/services/core/records.py` | 接口测试：新增 / 更新 / 置空 / 重复拒绝 |
| C6 | 「按通用逻辑」 | 写入复用现有记录写路径：表级 `EDIT_RECORDS`、行级权限、修改申请（202）、403 / 404 口径全部沿用，不为矩阵新造权限模型。表存在行级权限规则时矩阵只读（避免看不到已有行而重复建行）；必填字段被权限隐藏时返回明确错误 | `records.py`、`row_access.py`、`change_requests/services.py`、`tables.py` | 接口测试：viewer / 修改申请 / 行规则 / 隐藏字段 |
| C7 | （边界） | 可编辑矩阵只支持：行字段=单选、月份字段=日期、评分字段=数字（number / float / percentage）；月份范围 ≤24；视图不得同时配置筛选条件；表存在其他无默认值的必填字段时，新建单元格返回 400 并说明原因 | 视图配置校验 + `records` 写路径 | 单测：各非法配置 400；必填字段 400 |
| C8 | （兼容与验收） | 未配置评分字段的矩阵视图行为不变（只读卡片）；不新增表 / 列 / 枚举，无迁移，备份无需变更；前端样式沿用 `--cn-*` token，不新增重型依赖 | 全仓 | `make flow` + 前端单测 + e2e |

约束编号在实现中原样引用；不重编号、不合并。
