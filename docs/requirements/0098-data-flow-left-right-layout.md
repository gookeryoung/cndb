# 需求卡片：数据流程 UI 采用质量检查式左右列表 + 两级流程图

- 来源 / 提出人：用户（会话 2026-11-04）
- 日期：2026-11-04
- 关联 ADR：无（S1，纯前端 UI 重构；数据流程接口 / 数据模型不变，沿用 ADR 0097）

> 本卡片是**需求原文与约束编号的唯一副本**：需求变更后先改这里，再改代码。

## 需求原句（逐字）

> 数据流程，UI布局参考质量检查左右列表布局，顶部描述信息和文字信息过多需精简；两级流程UI命名为流程图，描述说明精简,UI设计得更紧凑；展开收起按钮合并为单个图标按钮

## 可实施约束（C1..Cn）

| # | 需求句（原文片段） | 可实施约束 | 涉及模块 | 验收方式 |
|---|---|---|---|---|
| C1 | 「UI 布局参考质量检查左右列表布局」 | 页面改为 `cn-qc-split` 左右双栏：左栏流程图列表、右栏当前子过程数据维护；复用 `cn-page` / `cn-page-head` / `SectionBox` / `cn-qc-row` / `cn-list-item` | `DataFlowPage.tsx`、`index.css` | 前端单测：左右两栏存在，数据表在右栏，流程图在左栏 |
| C2 | 「两级流程 UI 命名为流程图」 | 左栏分区标题固定为「流程图」；两级结构 = 一级大过程（流程）+ 二级子过程（步骤），子过程行缩进 | 同上 | 断言左栏含「流程图」标题与两级节点 |
| C3 | 「顶部描述信息和文字信息过多需精简」 | 去掉顶部大标题 + 说明 Alert；改用紧凑页头（图标 + 标题 + 单行 meta：模板 / 当前阶段 / 流程数），右侧仅刷新图标 | 同上 | 页面不再出现长说明块；页头仅一行 meta |
| C4 | 「描述说明精简，UI 设计得更紧凑」 | 一级节点只保留名称 / 主流程标识 / 子过程数 / 表单数；二级节点只保留名称 / 表单或审批标识 / 记录数；不展示长 description | 同上 | 断言长描述不出现在列表 |
| C5 | 「展开收起按钮合并为单个图标按钮」 | 移除「展开全部 / 收起全部」两个文字按钮，合并为一个图标按钮（全部展开时显示收起图标，否则展开图标），通过 aria-label / title 说明 | 同上 | 单测：一个 `data-flow-toggle-all` 按钮完成展开 / 收起切换 |
| C6 | （数据 CRUD 不变） | 右栏保留列表 / 搜索 / 新建 / 编辑 / 删除；审批 / 确认节点展示空态；写路径仍复用 records API | 同上 | 既有 CRUD 用例通过 |
| C7 | （响应式 / 工程口径） | `cn-qc-split` 窄屏单列；使用已登记断点与 `--cn-*` token；不新增接口 / 数据模型；CHANGELOG / CONTEXT 同步 | `index.css`、文档 | `tokens.test.ts`、前端全量测试、`make check-fast` |

约束编号在实现中原样引用；不重编号、不合并。
