## 需求原句（逐字）

> 文档列表页面，手机端，顶部 Ui 设计不够紧凑，请优化布局。

> 文档，文件夹和文档列表，手机端页面不够紧凑，请优化布局。（2026-11-03 追加整页口径）

## 可实施约束（C1..Cn）

| # | 需求句（原文片段） | 可实施约束 | 涉及模块 | 验收方式 |

## 未决问题（已全部有结论）

- [x] 筛选控件：**默认收起**，由「筛选」按钮展开（常显三等分会持续占掉第三行）。等价方案「把筛选也塞进更多菜单」被否决：筛选是列表高频操作，埋在混杂销毁性操作的菜单里不合语义。
- [x] 排序位置：**常驻操作行**。排序是列表级高频动作且与侧栏共享偏好（需求 0065），不随低频筛选一起收起。
- [x] 已应用筛选的收起态提示：**计数徽标 + aria-label**（测得到、读屏可读），不额外常显当前筛选文本。
- [x] 返回上级：移动端**只留图标**（`aria-label="上一级"`），桌面保持「上一级」文字按钮。
- [x] 桌面端：**完全不动**（C6）。
- [x] 控件尺寸：顶栏不缩小（C4），行尾操作保持 24px 点击区；紧凑靠减少行数与留白。
- [x] 文件夹卡片：移动端**两列自适应**（最小 150px），不改成列表行——保留系列状态分布的可扫视性。
- [x] 文档行操作：移动端**收进「更多」下拉**，删除仍二次确认；桌面四枚常驻图标不变。
