## 需求原句（逐字）

> 文档列表页面，手机端，顶部 Ui 设计不够紧凑，请优化布局。

## 可实施约束（C1..Cn）

| # | 需求句（原文片段） | 可实施约束 | 涉及模块 | 验收方式 |
|---|---|---|---|---|
| C1 | 「顶部 Ui 设计不够紧凑」 | 移动端（`isMobile`）文档列表页工具栏由**固定三行**收敛为**默认两行**：第一行导航（返回 / 面包屑 / 更多），第二行操作（搜索 / 筛选 / 新建），行间距与底边距下调 | `frontend/src/pages/documents/DocumentsPage.tsx` | 前端单测：移动端工具栏内只有导航行与操作行两个直接子块；`doc-order-select` 默认不在 DOM |
| C2 | 「请优化布局」 | 排序 / 标签 / 状态三个筛选控件默认收起，由一个「筛选」按钮展开为第三行；展开后三项仍为三等分且全部可用 | 同上 | 前端单测：点击 `doc-toolbar-filter` 后 `doc-order-select` / `doc-tag-filter` 出现且可见，再次点击收起 |
| C3 | 「优化布局」（状态可见性） | 收起态仍能看出已应用筛选：按钮以计数徽标 + `aria-label`（`筛选（已应用 N 项）`）表达，排序非默认、标签、状态各计 1 项 | 同上 | 前端单测：`?tag=7` 深链下筛选按钮 `aria-label` 含「已应用 1 项」，且筛选行默认收起 |
| C4 | 「不够紧凑」（不牺牲可用性） | 主要可点元素高度不下降：搜索框、筛选 / 更多 / 新建按钮继续使用默认尺寸（32px），不通过缩小控件换空间 | 同上 | 代码评审 + 前端单测断言筛选行展开后控件可见可点 |
| C5 | 隐含（入口不丢失） | 回收站 / 导入文件 / 导入 Obsidian 库 / 导出 / 新建文件夹继续收在「更多」菜单；返回上级、面包屑、标题过滤、新建文档、排序、标签、状态筛选能力全部保留 | 同上 | 前端单测：既有「更多」菜单用例与筛选用例全绿 |
| C6 | 隐含（桌面不变） | 桌面端（`!isMobile`）工具栏结构与行为完全不变 | 同上 | 既有桌面端排序 / 标签 / 回收站用例不改断言即通过 |
| C7 | 隐含（区段留白） | 移动端「最近打开」条与系列详情卡的上下留白同步收窄，不再在工具栏之下叠加一条宽松留白 | `DocumentsPage.tsx`、`frontend/src/index.css` | 代码评审 + 移动端单测仍能取到 `doc-recent` |

约束编号在 ADR 中原样引用；不重编号、不合并。

## 未决问题（已全部有结论，2026-10-26）

- [x] 筛选控件：**默认收起**，由「筛选」按钮展开（常显三等分会持续占掉第三行）。等价方案「把筛选也塞进更多菜单」被否决：筛选是列表高频操作，埋在混杂销毁性操作的菜单里不合语义。
- [x] 已应用筛选的收起态提示：**计数徽标 + aria-label**（测得到、读屏可读），不额外常显当前筛选文本。
- [x] 返回上级：移动端**只留图标**（`aria-label="上一级"`），桌面保持「上一级」文字按钮。
- [x] 桌面端：**完全不动**（C6）。
- [x] 控件尺寸：**不缩小**（C4），紧凑靠减少行数与留白，不靠压缩可点区域。
