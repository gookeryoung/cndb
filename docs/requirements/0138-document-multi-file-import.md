# 需求卡片：文档导入支持一次多选多个文件

- 编号：0138
- 来源 / 提出人：用户（会话 2026-11-22）
- 日期：2026-11-22
- 关联 ADR：`docs/adr/0010-document-file-import.md`（S1，复用既有批次导入管线，增量并入本卡片）

> 本卡片是**需求原文与约束编号的唯一副本**：需求澄清后先改这里，再改代码。

## 需求原句（逐字）

> cndb 项目的文档导入需要支持多选文件，让用户一次导入多个文档，而不是逐个导入。
>
> 后端与前端都需要相应支持：选文件时允许多选，导入流程能承载多个文件（含部分失败时的结果呈现）。

## 可实施约束（C1..Cn）

| # | 需求句（原文片段） | 可实施约束 | 涉及模块 | 验收方式 |
|---|---|---|---|---|
| C1 | 「选文件时允许多选」 | 通用导入弹窗的文件选择控件加 `multiple`；模式名由「单文件」改为「多文件」，副标题注明「支持多选」；一次选中的 N 个文件全部进入同一批次（每个文件一条，路径取文件名），仍受既有批次上限（条目数 / 总体积）约束，超限由后端 400 明确提示 | `frontend/src/pages/documents/DocumentImportModal.tsx` | 前端单测：input 带 `multiple`；一次选 3 个文件时 `analyze` 收到 3 条 entries、已选行显示「已选 3 个文件」 |
| C2 | 「导入流程能承载多个文件」 | 后端沿用既有多文件批次管线（`files: list[UploadFile]` + 一一对应的 `paths`），前端一次提交整批；同批同名文件按冲突策略（改名 / 跳过 / 覆盖）处理，不静默互相覆盖 | `src/cndb/plugins/documents/routers/file_import.py`、`services/importers/importer.py` | 接口测试：同批两个文件均落库（既有用例覆盖）；同批同名走冲突策略 |
| C3 | 「部分失败时的结果呈现」 | 单条落库异常（磁盘 / 数据库异常）不得中断整批：回滚本条事务、清理本条已落盘但未登记归属的附件（不留孤儿文件与错误配额）、计入 `skipped` 并写入 `skipped_files`（原因前缀「导入失败：」），其余文件照常导入；返回值契约不变 | `services/importers/importer.py` | 接口测试：一条模拟落库失败 + 一条正常时返回 200、created=1 / skipped=1、附件与归属登记均被清理 |
| C4 | 「部分失败时的结果呈现」（前端） | 结果页按落库篇数区分三态：全部成功 = 成功提示；部分成功 = 警告「部分文件导入完成（跳过 N 个）」；全部被跳过 = 错误「没有导入任何文件」，不谎报成功；跳过明细标注总数，超过 10 条时提示「仅列出前 10 个，其余 N 个未列出」；顶部消息同步区分成功 / 部分 / 失败 | `frontend/src/pages/documents/DocumentImportModal.tsx` | 前端单测：部分跳过走 `ant-alert-warning`、全部跳过走 `ant-alert-error`、明细截断提示 |
| C5 | （说明与文档） | 弹窗内格式说明、导入按钮 tooltip、帮助教程「导入文档库」同步改为多文件口径；CHANGELOG 记录 | `DocumentImportModal.tsx`、`DocumentsPage.tsx`、`help/content/tutorials.tsx`、`CHANGELOG.md` | `make check-docs` + 前端文案断言 |

约束编号在实现中原样引用；不重编号、不合并。

## 未决问题（已确认）

- [x] ① 交互形态：**结论**沿用同一弹窗的「多文件」模式（不新开批量导入页），一次选择多个文件后统一预览再导入。
- [x] ② 部分失败口径：**结论**单条失败隔离，成功条目照常落库，失败条目连同原因进跳过明细；全部失败时前端不得显示成功。
- [x] ③ 冲突处理：**结论**沿用既有冲突策略（默认改名），同批同名不静默覆盖。
- [x] ④ 方案分级：**结论**S1（接口契约不变，仅前端多选 + 逐条错误隔离与结果呈现）。
