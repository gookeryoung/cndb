## 方案（信息架构 + 布局）

### 1. 层级模型与导航原则

```
团队（组织层，单层扁平）  ──  工作区（工作上下文，唯一权限边界）  ──  模块（数据表 / 文档 / 设计 …）
```

三条原则：

1. **组织层只出现在「选择器 + 面包屑 + 团队页」**，不新增常驻导航条（保持 44px 顶栏与现有侧栏形态，避免第三个导航轴）。
2. **选择与浏览分离**：切换器负责「快速跳转」，团队页负责「浏览与管理」，首页负责「按团队浏览工作区」。
3. **同一数据一套分组纯函数**：团队归属分组、排序、扁平化提交都在 `utils` 层，桌面 / 移动 / 团队页复用。

### 2. 入口矩阵（现状 → 目标）

| 位置 | 现状 | 目标 | 依据 |
|---|---|---|---|
| 顶栏切换器 | 平铺工作区菜单 | 分组面板：搜索（>8 项时）+ 已收藏 + 团队分组（组头带计数 / 角色 / 管理入口）+ 个人工作区 + 底部「全部工作区 / 新建工作区 / 管理团队」 | GitHub / GitLab 的 owner›repo 切换器；C1 / C2 |
| 顶栏面包屑 | 仅工作区名 | `团队名 › 工作区名 ▾`（团队名可点回团队页；个人工作区显示「个人」）；移动端只保留切换器 | C4 |
| 首页 `/w` | 标题 + 团队下拉 + 「团队」按钮 | 团队 chips（全部 / 个人 / 各团队，带计数，持久化）+ 分组 section 列表；团队 section 头带「管理」链接；工具栏只保留搜索 / 新建 / 导入 | C1 / C2 / C8 |
| 团队页 `/teams` | 左卡 + 五卡片纵向堆叠 | `/teams/:tid?section=`：团队头部（切换器 + 指标 + 主操作）+ 分区页签；左侧列表移除 | C3 / C8 |
| 移动端导航 | 汉堡抽屉 = 当前工作区侧栏 | 抽屉顶部加「团队」分组（团队 → 工作区两级，默认收起），其余不变 | C7 |

**不重复**：首页保留「管理团队」文本链接（section 头），顶栏切换器底部保留同一入口，团队页内不再放「团队列表」卡片；三处都指向同一路由，不产生第二种交互。首页工具栏的独立「团队」按钮移除（避免与 chips / section 头重复）。

### 3. 顶栏切换器（`ScopeSwitcher`）

```
┌ 工作区名 ▾ ─────────────────────────────┐
│ 🔍 搜索团队 / 工作区（>8 项时出现）        │
│ ★ 已收藏                                 │
│   ▦ 产品研发            [所有者]          │
│ ── 研发部  6 个 · ⚙管理 ─────────────────│
│   ▦ 数据中台            [编辑者]          │
│   ▦ 质量看板            [查看者]          │
│ ── 个人工作区  3 个 ─────────────────────│
│   ▦ 我的试验田          [所有者]          │
│ ─────────────────────────────────────────│
│ 全部工作区            新建工作区  管理团队 │
└──────────────────────────────────────────┘
```

- 复用 `useQuery(['workspaces'])` 与 `['teams']` 缓存，不新增请求；分组由纯函数生成。
- 团队组头不可点击切换上下文（避免「进入团队页」与「展开组」混淆）：组头右侧「管理」按钮显式跳团队页；组内即工作区跳转。
- 键盘：↑↓ 移动、Enter 进入、Esc 关闭、输入框自动聚焦；`role="menu"` / `aria-current` 标注当前项。
- 移动端：同一组件以 Drawer / Popover 全宽呈现，触摸目标 ≥32px。

### 4. 首页布局（`/w`）

```
工作区                                             [搜索] [新建工作区] [导入]
按团队分组；已收藏置顶，团队内工作区平铺（无树）
[全部 12] [个人 3] [研发部 6] [市场部 3]        ← 团队 chips（sticky，可持久化）
┌ ★ 已收藏 (2) ─────────────────────────────────────────────┐
│  ⇅ ▸ ▦ 产品研发   …                                       │
└───────────────────────────────────────────────────────────┘
┌ 研发部   6 个工作区 · 你是团队成员            [管理团队] ─┐
│  ⇅ ▸ ▦ 数据中台   …                                       │
│  ⇅ ▸ ▦ 质量看板   …                                       │
└───────────────────────────────────────────────────────────┘
┌ 个人工作区   3 个工作区 ──────────────────────────────────┐
│  ⇅ ▸ ▦ 我的试验田   …                                     │
└───────────────────────────────────────────────────────────┘
                                              （右侧「我的视图」不变）
```

- **默认分组展示**（不是筛选后才有分组），chips 只是快速收窄；再次点击当前 chip 回到「全部」。
- 「已收藏」保持在最上方且**不在团队分组内重复**；团队分组内按既有 `workspace_order` 排序。
- 分组头可折叠，折叠态持久化（`cndb_home_group_collapsed`），筛选词命中时自动展开。
- 团队 chip 激活时点「新建工作区」→ 新建弹窗 `team_id` 预填该团队（已有字段，`WorkspaceList.tsx:420`）。
- 拖拽排序：仅在**同一分组内**生效；提交顺序 = 按当前渲染的分组顺序拼接各组内顺序（新增 `flattenGroupedOrder` 纯函数），搜索过滤或跨组拖拽时禁用（沿用现状口径）。
- 无团队：不渲染 chips 与团队分组，仅「已收藏 / 其他工作区」——与现状逐像素等价（C9）。

### 5. 团队页布局（`/teams/:tid?section=`）

```
┌ [研发部 ▾]  研发部   [团队成员]      6 工作区 · 12 人   [新建工作区] [团队设置] ┐
│ 概览 │ 工作区 │ 成员 │ 策略 │ 搜索                                             │
├───────────────────────────────────────────────────────────────────────────────┤
│ 概览：指标卡（工作区 / 成员 / 你的角色 / 策略摘要）+ 最近工作区 + 搜索入口        │
│ 工作区：平铺表格（名称 / 模块 / 成员数 / 是否已加入 / 加入 / 打开）               │
│ 成员：成员表 + 添加成员（owner/admin 可见；owner 可改角色）                       │
│ 策略：owner 可编辑表单，其余只读；危险区「删除团队」独立卡片（含「不删工作区数据」）│
│ 搜索：团队内文档 / 表 / 行检索（现有能力，独立分区）                              │
└───────────────────────────────────────────────────────────────────────────────┘
```

- 路由：`/teams` → 有团队时 `Navigate` 到第一个团队 `overview`；无团队保留空态 + 「新建团队」；`/teams/:tid` → 默认 `overview`；非法 / 非成员 → 友好空态 + 返回团队列表（不泄露存在性）。
- 分区用 `?section=`（与工作区设置 / 统计页同范式），刷新 / 回退 / 分享保持；页签键盘可操作。
- 团队切换器放页头（与顶栏切换器同组件形态，compact 版），移除左侧「我的团队」卡片，内容区拿整幅宽度（窄屏单列）。
- 「新建工作区」按钮在团队页预填 `team_id`；「团队设置」跳到 `?section=policy`。
- 头部明确保留两平面提示（团队管理员默认读不到数据），文案沿用现有口径，不改语义。

## 决策（方案内定，无需 ADR）

| # | 议题 | 结论 | 依据 / 否决项 |
|---|---|---|---|
| N1 | 是否新增常驻「团队」导航栏 | 否：只做切换器 + 面包屑 + 团队页 | 已有顶栏 / 工作区页签 / 侧栏三条导航轴，再加一条会挤压内容区；GitHub 也只用 owner 切换器 |
| N2 | 首页默认平铺还是分组 | 分组（已收藏 → 团队 → 个人），chips 收窄 | C1；筛选器方案（现状）默认看不到层级 |
| N3 | 团队页是否保留左侧团队列表 | 移除，改页头切换器 | 双入口重复（C2）；窄屏下左卡挤占内容宽度 |
