# 需求卡片：数据流程 UI 改为横向大过程 + 纵向子过程节点流

- 来源 / 提出人：用户（会话 2026-11-04）
- 日期：2026-11-04
- 关联 ADR：无（S1，纯前端 UI 重构；数据流程接口 / 数据模型不变，沿用 ADR 0097）

> 本卡片是**需求原文与约束编号的唯一副本**：需求变更后先改这里，再改代码。

## 需求原句（逐字）

> 优化数据流程UI，按照横向节点流+纵向节点流模式设计，横向节点标识大过程，纵向节点流标识每个大过程的子过程

## 可实施约束（C1..Cn）

| # | 需求句（原文片段） | 可实施约束 | 涉及模块 | 验收方式 |
|---|---|---|---|---|
| C1 | 「横向节点流」 | 页面顶部以大过程为单位渲染横向节点流：每个流程一个节点，节点间用连接线 / 箭头串联，支持横向滚动；选中大过程高亮 | `frontend/src/pages/dataFlow/DataFlowPage.tsx`、`frontend/src/index.css` | 前端单测：多流程节点同时渲染、点击切换；视觉窄屏可横向滚动 |
| C2 | 「横向节点标识大过程」 | 横向节点展示流程名、描述、子过程数 / 表单数 / 记录数；保留「主流程」「当前查看」标识 | 同上 | 前端断言：节点文案含流程名与统计 |
| C3 | 「纵向节点流标识每个大过程的子过程」 | 选中大过程后，左侧以纵向节点流展示其 steps：节点序号 + 子过程名 + 表单 / 审批节点标识；步骤间有纵向连线；点击切换子过程 | 同上 | 前端单测：纵向节点切换、审批节点无 CRUD |
| C4 | 「数据 CRUD 不受影响」 | 右侧详情区沿用 0095/0097：有表单子过程可列表 / 搜索 / 新建 / 编辑 / 删除；无表单子过程展示审批空态 | 同上 | 既有 DataFlowPage 用例继续通过；新增节点切换用例 |
| C5 | （响应式） | 桌面端左右两栏（纵向节点 + 详情）；窄屏纵向排列，纵向节点区域可达 | `frontend/src/index.css` | 断点使用已登记 `767.98px`；tokens 单测通过 |
| C6 | （工程口径） | 不新增接口 / 数据模型；CHANGELOG / CONTEXT 同步；前端全量测试通过 | 文档 | `make check-fast` / `pnpm test` |

约束编号在实现中原样引用；不重编号、不合并。
