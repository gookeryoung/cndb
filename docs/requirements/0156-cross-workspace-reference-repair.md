## 需求原句（逐字）

> 请立项P2解决引用自动修复问题

## 背景（ADR 0155 的既定限制）

跨工作区移动保留文档 id、版本链与站内文件，但**引用不会被自动修复**：

- 正文里的 `[[标题]]`（双链）在**当前工作区**内按标题解析 → 被移动文档内部指向「留在源工作区」的文档，移动后即断链；
- 正文里的 `{{table:<表ID>|view=…}}`（数据表动态引用）指向**源工作区**的数据表 → 移动后解析失败（表不在目标工作区，或被权限拒绝）；
- 反向同理：源工作区里指向「被移动文档」的 `[[标题]]` 在移动后也断链。

ADR 0155 的移动弹窗已提示「不会自动修复」，本需求要把这条限制补上。

## 可实施约束（C1..C10）

| # | 需求句（原文片段） | 可实施约束 | 涉及模块 | 验收方式 |
|---|---|---|---|---|
| C1 | 「引用」「修复」 | 能**诊断**一次移动影响到的全部引用，分两个方向：① 被移动文档内 → 指向源工作区（`[[标题]]` 目标在源工作区 / `{{table:id}}` 表在源工作区）；② 源工作区其他文档内 → 指向被移动文档（按标题）。每条给出：所在文档、引用原文、目标类型、失效原因、目标工作区名 | `documents` 插件 | 单测 / 接口测试：两方向用例 |
| C2 | 「自动修复」 | 提供三种**显式**策略（默认 `none`）：`none` 保留原样；`annotate` 把失效引用改写为带说明的静态文本（`[[标题]]（已移至「工作区名」）`）；`snapshot` = annotate + 把 `{{table:…}}` 落为静态 GFM 表格快照（复用导出侧 `rewrite_markdown_table_refs` 与同一 resolver） | `documents` 插件 | 接口测试：三策略产物逐条断言 |
| C3 | （可预览） | 修复默认**预览**（不落库）：`POST …/documents/references/preview` 返回每条引用的「原文 → 新文」与受影响文档清单；确认后才执行 | `documents` 插件 | 接口测试：预览不改库；执行才生成版本 |
| C4 | （可接在移动上） | 移动可携带 `repair_strategy`（`none|annotate|snapshot`，默认 `none`），选择后**在同一次请求内**完成「移动 + 修复」；被移动文档的修复各自生成新版本 | `documents` + `move` | 接口测试：带策略移动后正文已改写且版本 +1 |
| C5 | （反向引用） | 源工作区其他文档对被移动文档的 `[[标题]]` 只能 `annotate`（跨区无法解析）；执行需源工作区 `WRITE`，且只改**受影响行**（不整体重排正文） | `documents` 插件 | 接口测试：源侧文档被注释、其他内容不变 |
| C6 | （可追溯） | 修复生成新版本：`change_type` 新增 `move_repair`，`change_summary` 写「跨工作区移动引用修复」；两侧各记 `core_event`（`documents.references_repaired`，不含正文） | `documents` + `core.events` | 接口测试：版本与事件 |
| C7 | （幂等 / 不覆盖） | 已无残留引用 → 200 空操作（不生成版本）；文档版本在预览后被他人推进 → 按最新版本重算（不覆盖），或 409 `stale_version`（二选一，见 ADR D6）；草稿不参与修复（只改已提交版本） | `documents` 插件 | 接口测试：二次修复空操作、并发推进 |
| C8 | （不静默） | 仍为 `none` 时，文档页对失效引用显示提示（「引用已失效：目标已移至『工作区名』」/「数据表不在当前工作区」），导出侧保持现有降级文案 | `documents` + 前端 | 前端单测：提示渲染 |
| C9 | （有界） | 单次修复 ≤200 篇文档；扫描复用 `iter_wikilinks` / `parse_table_ref_line`，不引新依赖；`snapshot` 每表行数沿用导出上限 | `documents` 插件 | 接口测试：超限 400 |
| C10 | （存量不变） | 默认策略 `none`；不调用修复时正文、版本、导出与升级前逐条一致（H13 / H14 不触发） | 全链路 | 存量用例全绿 |

非目标（本期不做）：跨工作区「活引用」（`{{table:}}` 直接读源工作区的表——依赖 ADR 0154 链接获批与其 P1+ 能力，见 ADR D8 的评估项）、移动撤销、把双链改写成新的跨区 URL 语法、引用关系图形化。

## 未决问题

- [x] ① 修复是否默认开启：**默认 `none`**（移动是破坏性操作，正文改写必须显式选择）。
- [x] ② `{{table:…}}` 的修复方式：`annotate`（注释掉）或 `snapshot`（静态表格快照）；「活引用」依赖 ADR 0154，不在本期。
- [x] ③ 反向引用：只做 `annotate`（跨区无法解析标题），需源工作区 `WRITE`。
- [x] ④ 是否新增版本类型：**新增 `move_repair`**（可回滚、可审计）。
- [ ] ⑤ 并发冲突口径：按最新版本重算 vs 409（ADR D6，待确认）。
