## 可实施约束（C1..C7）

| # | 需求句（原文片段） | 可实施约束 | 涉及模块 | 验收方式 |
|---|---|---|---|---|
| C1 | 「健壮性」 | **只读体检**：`diagnose()` 对指定范围（默认全部活动表）逐表检查，产出结构化报告（每项：表、问题、条数、样例 id），不改数据 | `services/core/table_doctor.py` | 单测：四类问题各 1 例 + 干净库 0 误报 |
| C2 | 「孤儿 link」 | 关联表里 `row_id` 指向不存在/已软删的源行、或 `target_row_id` 指向不存在/已软删目标行 → 计入 `orphan_links`；样例最多 10 条 | 同上 | 单测：删源行/物理删目标行后检出 |
| C3 | 「失效 lookup 冗余列」 | 消费方 `_lk_*` 与其当前源值不一致 → 计入 `stale_lookup`（按字段汇总 + 行数）；旧库缺列不算问题 | 同上、`lookup_sync` | 单测：手工篡改 `_lk_*` 后检出 |
| C4 | 「排序索引漂移」 | 物理表上形如 `ix_*_sort_*` 的索引，若当前所有视图 `sortings` 都不再需要它 → 计入 `orphan_sort_indexes`；仍在用的不报 | 同上、`ddl.ensure_sort_index` | 单测：改视图排序后原索引变孤儿 |
| C5 | 「回收站体积」 | 统计每表已软删行数、`_trashed_at` 为空（时间未知）行数、可清理行数（按 `TRASH_RETENTION_DAYS`） | 同上、`rows_retention` | 单测：软删 2 行后统计正确 |
| C6 | 「可修复」 | `--fix` 只做**幂等**修复：删孤儿 link 关系（并重算受影响消费方 `_lk_*`）、按字段重算失效 lookup 冗余列、DROP 孤儿排序索引；**不删除任何行**（行清理走 `purge-trash`，ADR 0139 D4） | 同上 | 单测：`--fix` 后再次体检为 0；软删行数不变 |
| C7 | （契约） | 报告可 JSON 输出；退出码恒 0（体检不是门禁）；`--workspace/--table` 可收窄；公式异常检测不在本期（需逐行求值，记入路线图后续） | `cli/tables.py` | 单测：JSON 形状 + 范围收窄 |

约束编号在实现中原样引用；不重编号、不合并。
