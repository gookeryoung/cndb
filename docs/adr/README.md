# ADR 索引

> `Status` 口径：`Proposed`（待评审）/ `Accepted`（已评审）/ `Implemented`（已落地）。
> `Accepted` 表示已评审通过但仍有未开始分期；分期全部落地的 ADR 一律置 `Implemented`（`make adr-check` 会对「全期落地仍为 `Proposed`」告警）。
> 合并 / 删除过的编号见下方「索引约定」，其内容保存在父 ADR 的「续作」小节里。
> 落地阶段以各 ADR「落地状态」表为准；进度、下一步与已知坑看「交接」节。
> 本索引按**功能域**分组（域内按编号升序），每节末尾是该域内 ADR 的承接关系；跨域引用一律走编号。
> `make adr-check` 校验本索引、ADR 落地表与代码 / 测试 / CHANGELOG 的对应关系。

## 索引约定

- 一个 ADR 只属于一个域；跨域的内容写在「与既有 ADR 的关系」表里，不复制。
- ADR 被新方案替代或需求作废时**直接删除**该文件与本索引行（不保留 `Superseded` / `Deprecated`，追溯看 `git log -- docs/adr/`），编号不复用。
- 编号缺口（0001 / 0007 / 0009 / 0011 / 0013 / 0033 / 0053 / 0061–0073 / 0078 / 0081 / 0082 / 0085）是已删除或只留需求卡片的编号，属正常，不要复用。
- **已并入的编号**（ADR 文件已删除，内容作为父 ADR 的「续作」小节保留，代码注释里的旧编号仍指向该小节）：0015→0012（搜索缓存与全表覆盖）、0040→0037（同步速度展示）、0058→0048（插入图表多级列表）、0059→0056（联动单元格显示）、0060→0052（图表点击放大）、0077→0023（dashboard 导出与只读分享）。
