# 2026-10-11

## CI release 失败修复：fspack wheel 下载 PEP 658 metadata 404

**现象**：Release workflow 的 pack-windows job 失败
```
ERROR: HTTP error 404 while getting https://mirrors.aliyun.com/pypi/packages/.../cryptography-42.0.8-cp39-abi3-win_amd64.whl.metadata
```

**根因链**：
1. fspack 默认 `DEFAULT_MIRROR = "aliyun"`（config/models.py:149），CI 未指定 `--mirror`，所以 pip index = 阿里云
2. pip 按 PEP 658 走 metadata-only 解析，请求 `<wheel>.metadata`
3. 阿里云/腾讯云镜像 index 页面声明支持 PEP 658，但 `.metadata` 文件未同步 → 404
4. pip（含最新 26.1.2）遇到 404 直接失败，**不回退**到下载完整 wheel

**实测数据**（同一个 wheel 的 `.whl` / `.whl.metadata`）：
| 源 | whl | metadata |
|---|---|---|
| mirrors.aliyun.com | 200 | 404 |
| mirrors.cloud.tencent.com | 200 | 404 |
| mirrors.huaweicloud.com | 200 | 200（但 simple index 返回 SPA 兜底页，缺 cryptography 42.0.8，不可用） |
| pypi.tuna.tsinghua.edu.cn | - | 403 |
| pypi.org / files.pythonhosted.org | 200 | 200 ✅ |

**修复**：`release.yml` 中 `fspack b` 加 `--extra-index-url https://pypi.org/simple/`（pack-windows + pack-linux 两个 job）。本地已验证 `-i aliyun --extra-index-url pypi.org` 清缓存后下载成功。

**注意**：
- 该参数**只有 `fspack build` 支持**，`fspack package` 的 help 里没有（`--no-build` 时不下载 wheel，无需加）
- `--extra-index-url` 会进入 `_deps_cache_key`，旧 `~/.fspack/cache/.deps-*.json` 缓存会 miss，属预期（需要重新解析）
- fspack 0.6.11 已是 PyPI 最新版，无自定义 pypi index 的支持，无法直接改主索引

## 沙箱 corepack/pnpm 下载链路损坏修复

**现象**：`pnpm` 任何命令报 `Cannot find module '/root/.cache/node/corepack/v1/pnpm/12.4.2/bin/pnpm.cjs'`；`corepack prepare` 假成功（exit 0 但缓存里只有 `bin/pnpm.mjs`，无 `pnpm.cjs`）。

**根因**：Node 24 自带的 corepack（旧版）按旧包结构硬编码找 `bin/pnpm.cjs`，而 pnpm 12 改为 `bin/pnpm.mjs` + `dist/` 新结构 —— 不是网络/代理问题，是 corepack 版本过旧不认识 pnpm 12。

**修复**（三步，缺一不可）：
```bash
npm install -g corepack@latest        # 1. 升级 corepack
rm -rf /root/.cache/node/corepack/v1/pnpm   # 2. 清旧结构缓存（新版仍会读取 v1 路径）
corepack enable pnpm && pnpm --version      # 3. 重建 shim + 验证（新版会额外下载 pnpm 原生二进制）
```

**教训**：`corepack prepare` 假成功时要看缓存目录实际内容判断包结构；npm -g 装 pnpm 会覆盖 corepack shim 且卸载后 shim 一起消失，非长久方案。
