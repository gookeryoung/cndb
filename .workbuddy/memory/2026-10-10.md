### 关键发现：imports 的 URL 必须是 `/-/git/raw/`

**这是本轮最重要的坑，且官方文档示例是错的。**

实测同一文件三种路径：

| 路径 | 返回内容 |
|---|---|
| `/-/raw/main/f.yml` | HTML「Page not found」页面 |
| `/-/blob/main/f.yml` | HTML 页面 |
| `/-/git/raw/main/f.yml` | ✅ 真实文件内容 |

官方语法文档示例写的是 `/-/blob/`，**照抄会让流水线把 HTML 当 YAML 解析**，
报错信息极具误导性（表现为 YAML 语法错误，而非「URL 错了」）。

正确写法：`https://cnb.cool/<slug>/<repo>/-/git/raw/<ref>/<path>`

> 判定方法：`curl -s <url> | head -c 200`，若看到 `<!DOCTYPE html>` 就是错了。

### CDN 缓存会骗人

文件刚推到 CNB 时，`curl` 仍返回旧的 404 HTML 页面（HTTP 200 + HTML）。
此时不要怀疑配置错误 —— 用 `cnb git get-content --repo <slug> --file-path <path>`
确认文件确实在远端（返回 blob + sha + size），再等 CDN 刷新。
`cnb git get-content` 走 API 不走 CDN，是判断「文件是否存在」的可靠手段。

### scp 不保留执行位（迁移时必踩）

GitHub Actions 的 `appleboy/scp-action` 之后有个独立的 `chmod` step，
迁移到 CNB 的裸 shell 后这个 step 容易丢。后果：`deploy.sh` 报 Permission denied。
必须在**同一个 stage 内**完成 scp + chmod —— 跨 stage 改权限在只读挂载下不可靠。

已在同步 stage 补：
```
$SCP deploy/deploy.sh deploy/backup.sh deploy/nginx.conf deploy/bootstrap-server.sh ...
$SSH ... 'chmod +x /opt/cndb/deploy/*.sh && ls -l /opt/cndb/deploy/'
```

### 新增 deploy/bootstrap-server.sh

服务器首次初始化的幂等脚本。设计要点：

- **只补不覆盖**：`set_env()` 先 `grep -qE "^KEY="`，存在就跳过。
  覆盖 `.env` 会丢掉已配置的 JWT_SECRET 与域名，是最危险的操作。
  已用两种场景实测：全新服务器建全项；重跑零补写、零重生成。
- **先检查后写入**：docker / compose / openssl 全部检查完再动文件，
  避免检查失败却已改了一半配置。
- JWT_SECRET 用 `openssl rand -hex 32` 生成且**不回显明文**；
  占位符 `CHANGE_ME` 也视作未配置重新生成。
- `CORS_ORIGINS` 必须按 JSON 数组写 `["http://..."]`。
  pydantic-settings 对 `list[str]` 一律按 JSON 解析，逗号分隔会抛 SettingsError，
  表现为容器启动即崩且日志难定位。
- 兼容性降级：端口检查 `ss` 缺失时降级 `netstat`；磁盘检查 `df -BG --output`
  非 GNU 时降级 `df -g`。缺失时静默跳过而非报错中断。
- `--with-cron` 装每日 03:17 定时备份（避开整点）。

实测方式：`PATH` 里塞一个假 `docker` 脚本桩，用 `APP_DIR=/tmp/...` 跑完整流程，
验证幂等性与生成内容。本机无 Docker 时这是可行的验证手段。

###镜像地址散落在 5 处，必须同步改

这是本项目的固定维护成本，改仓库名时**5 处全改，漏一处就部署失败**：

| 文件 | 位置 | 形式 |
|---|---|---|
| `gkzhou/cndb-secrets/deploy-env.yml` | `TCR_REPO` | 流水线实际读这份 |
| `deploy/bootstrap-server.sh` | `REPO="cndb"` | 服务器首次初始化默认值 |
| `deploy/.env.prod.example` | `CNDB_IMAGE=` | 会被人工复制到服务器 |
| `deploy/cnb-secrets.example.yml` | `TCR_REPO` + 注释 | 主仓库模板（供复制到密钥仓库） |
| `docs/CNB.md` | 变量表 + 示例 | 文档 |

`.cnb.yml` 里**没有**硬编码仓库名 —— 用的是 `${TCR_REPO:-cndb}`，
这是当初把硬编码改成变量的收益体现。
